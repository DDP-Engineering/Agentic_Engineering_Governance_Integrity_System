## Frame

Problem: On Windows, AEGIS and the CodeGraph plugin start Git (and the core
starts `taskkill`) by bare program name. When `NoDefaultCurrentDirectoryInExePath`
is not set - the Windows default - process creation searches the current
directory first, and AEGIS runs with the repository root as its working
directory, so a `git.exe` or `taskkill.exe` committed at the repository root is
executed instead of the real program. That is running repository code, which
AEGIS and CodeGraph promise never to do. (STATED in the request; OBSERVED by
probe, below.)
Desired outcome: AEGIS and CodeGraph start Git and `taskkill` only from an
absolute location found on PATH outside the repository; a program inside the
repository is never executed; behavior on Linux and for ordinary PATHs is
unchanged.
Actors: a developer or agent running `python .agentic/aegis.py ...` in a
repository; the CodeGraph plugin started by the core; a repository author who
may commit a malicious executable.
Primary scenario: a repository contains `git.exe` at its root -> the operator
runs `python .agentic/aegis.py check` (or `know_graph_index`) from the root ->
AEGIS resolves Git from PATH, skipping the working directory and the
repository -> the real Git runs; the repository's `git.exe` never starts.
Examples: probe (OBSERVED, scratchpad, nothing committed): a copy of
`hostname.exe` named `git.exe` and `taskkill.exe` in a folder; launching
`["git"]`, `["git"]` with `cwd=`, and `["taskkill"]` from that folder ran the
copy on Windows Python 3.11.9, 3.12.10 and 3.14.6, and Node's `spawnSync("git")`
ran it too - but only with `NoDefaultCurrentDirectoryInExePath` removed from
the environment; with it set (as in this session) the real programs ran.
`shutil.which("git")` returned `.\git.EXE` without the variable on all three.
Counterexamples: configured `[commands]` entries (for example `pytest -q`) run
through the shell by design and resolve programs the operator configured; the
documented `python .agentic/aegis.py` invocation is resolved by the operator's
own shell before AEGIS starts; Git's own behavior inside the repository (hooks,
local config) is Git's trust model. None of these is changed here.
In scope: the core CLI `05_Software/aegis/template/.agentic/aegis.py` -
`run_git` (all Git calls go through it) and `kill_tree`'s `taskkill`; the
CodeGraph plugin `codegraph/scope.py` and `codegraph/safety.py` Git calls;
tests in `05_Software/aegis/tests/` and `05_Software/aegis/plugins/codegraph/tests/`;
mirrors (`.agentic/aegis.py`, `.agentic/plugins/codegraph/`); a new security
requirement; affected docs and knowledge pages.
Out of scope: the JavaScript host bridge (`05_Software/aegis/integrations/shared/adapter.mjs`
`git(...)` and the bare `'python'` fallback, `runtime.mjs` probes), which has
the same exposure (OBSERVED) - pending the user's decision (question 1);
configured `[commands]`; Git's hook and config behavior.
Constraints: standard library only in `aegis.py`; Windows and Linux; Python
3.11-3.14; root `.agentic/aegis.py` byte-identical to the template; Git missing
keeps degrading exactly as today (`run_git` returns None); no new dependency.
Success signals: with `NoDefaultCurrentDirectoryInExePath` removed and a
program-named executable in the repository root, `run_git`, `kill_tree` and the
plugin's Git calls start the real program (tests); an executable reachable only
through a PATH entry inside the repository or a relative PATH entry is refused
and treated as missing; all existing suites stay green on Windows and WSL.
Evidence: STATED - the request (task chip). OBSERVED - `aegis.py` `run_git`
(`["git", *args]`, `cwd=ROOT`) and `kill_tree` (`["taskkill", ...]`);
`scope.py` and `safety.py` (`GIT = "git"`); `adapter.mjs` `exec('git', ...)` and
`settings.python` default `'python'`; probe results above; this session's
environment sets `NoDefaultCurrentDirectoryInExePath=1`. INFERRED - users
running AEGIS from cmd or PowerShell without that variable are exposed; POSIX
`execvp` searches only PATH, so Linux is exposed only through relative or
repository PATH entries. UNKNOWN - none blocking.
Assumptions: an absolute program path found on PATH outside the repository is
trusted as the system's program.
Unknowns: whether CI or other Windows hosts set the variable (does not change
the fix).
Decision-blocking questions: (1) include the JavaScript host bridge in this
task, or record it as a follow-up; (2) stay on branch
`ddp/codegraph-plugin-plan` (the plugin exists only there) or stack a new branch.
Proposed behaviors: resolve each program once from PATH, skipping empty and
relative entries and any entry inside the repository, trying PATHEXT
extensions on Windows; refuse a resolved file inside the repository; start the
program by that absolute path; when none is found, behave as when the program
is missing today.
Path and reason: full - security behavior changes and no existing requirement
covers program resolution (quick-path criteria below).

## Design

**Requirements coverage.** REQ-SEC-283dff37 -> `system_program` in `aegis.py`,
used by `run_git` and `kill_tree`. REQ-SEC-8960c937 -> `codegraph/programs.py`
`find`, used by `scope._git` and `safety._git`.

**Component responsibilities.** Each component owns its resolver: the plugin
cannot import `aegis.py` (it runs isolated, `-I`), and the core must stay one
standard-library file. The two functions implement the same rule, about 25
lines each (technical constraint: separate processes and packaging).

**Interface.** `system_program(name) -> str | None` (core) and
`programs.find(name, root) -> str | None` (plugin): the absolute path of the
first match, or None. Rule (REQ-SEC-283dff37, REQ-SEC-8960c937): walk
`PATH` split on `os.pathsep`; strip surrounding quotes; skip empty entries,
relative entries and entries that resolve inside the repository root; on
Windows try `<name>.exe` only - as a bare-name launch does - never a `.cmd` or
`.bat`, which would run through `cmd.exe` and re-parse arguments such as
repository file names (decision revised in validate); on POSIX the name itself;
accept a regular file (POSIX: also executable); resolve it and refuse it when
the resolved file is inside the root (a link pointing into the repository).
Every candidate folder is resolved first and skipped when inside the root;
an unreadable folder or file counts as no match (`os.path.isfile`), never an
error; the resolved file path is returned and launched (decision revised in
validate). `shutil.which` is not used: on
Windows it searches the working directory too (observed in frame).

**Execution flow.** `run_git`: resolve `git`; None -> return None (the existing
"Git missing" path, so every caller degrades as today); else run
`[path, *args]` unchanged. `kill_tree` (Windows): resolve `taskkill`; None ->
treat as a refused kill (returns False after `proc.kill()`, as when taskkill is
missing today). Plugin `_git`: resolve with `settings.root`; None -> return None
(filesystem inventory, Git precondition skipped, status Git fields null - the
existing no-Git behavior).

**State.** The core caches by `(name, PATH, root)` in a module dictionary, so
repeated `run_git` calls in one `check` walk PATH once and a changed PATH (tests)
resolves again; the plugin resolves per call (few calls per run).

**Security and trust.** Trusted: absolute PATH locations outside the
repository. Not trusted: the working directory, relative PATH entries, PATH
entries or link targets inside the repository. Out of scope (Frame, RULING-001):
the JavaScript bridge, configured `[commands]`, Git's own hooks and config.

**Compatibility.** Normal Windows and Linux setups resolve the same Git as
before. A setup whose only Git sits inside the repository or behind a relative
PATH entry now reports Git as unavailable - the intended change. Python
3.11-3.14; no new dependency.

**Test seams.** Core: new `05_Software/aegis/tests/test_system_programs.py` -
with `NoDefaultCurrentDirectoryInExePath` removed and the process working
directory at a temporary repository root holding a fake `git` (Windows: a copy
of `hostname.exe` as `git.exe`; POSIX: an executable script), `run_git
("--version")` must report real Git; PATH limited to a repository folder with a
fake plus an empty and a relative entry must make `run_git` return None;
`kill_tree` on Windows must launch `taskkill` by an absolute path outside the
root (recorded through a `subprocess.run` wrapper) and stop the tree. Plugin:
`tests/test_scope.py` - a fake `git` in the root of a Git work tree must leave
`inventory=git`; `find` must refuse repository, relative and empty PATH entries.
The variable must be removed in every test, or the tests pass vacuously in this
environment (frame observation).

**Alternatives.** `shutil.which` (searches the working directory on Windows);
setting `NoDefaultCurrentDirectoryInExePath` for child processes (it governs
the parent's own search, so it would have to be set in AEGIS's environment -
works on Windows only and does not cover relative PATH entries); a fixed list
of install folders (breaks custom Git installs).

**Expected files.** `05_Software/aegis/template/.agentic/aegis.py` (+ mirror
`.agentic/aegis.py`); `05_Software/aegis/plugins/codegraph/codegraph/programs.py`
(new), `scope.py`, `safety.py` (+ dogfood copy); the two test files; knowledge
pages for the core CLI and CodeGraph; `CHANGELOG.md`.

**Risks.** A Windows Git reachable only through a `.cmd` shim now counts as
missing (Git for Windows installs `git.exe`); fakes in tests must be cleaned up. **Open decisions.** None.
No architecture drawing is owed: behavior inside existing functions plus one
helper module.
