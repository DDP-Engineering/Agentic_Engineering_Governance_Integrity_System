## Design

- Components: AEGIS Light payload instructions, companion CLI stage vocabulary, release inventory, and paired Markdown/PowerPoint user documentation.
- Interface: `status` recognizes `validate` and resolves it to `5_validate.md`; existing commands and exit behavior remain unchanged.
- Evidence: automated red work records the exact selector or command, non-zero exit, and expected missing-behavior reason as append-only journal prose; manual verification records the observation instead.
- Lifecycle: build advances to validate; validate performs every candidate-changing review/update and proves last; deliver publishes only and returns to validate if the candidate changes.
- Rejected alternative: Git witness commits and a `deliver` default zone were rejected because they add ceremony and the merge-base diff cannot attribute edits to a stage.
- Test seams: structural payload assertions cover instructions and no deliver zone; CLI status fixtures cover both new stage mappings; release inventory tests cover the renamed and added step files.
